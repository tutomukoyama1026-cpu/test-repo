# 椙山改修 定例会議 議事録・課題リスト自動格納システム（構築手順・Workato 版）

会議（総合定例会議・定例会議・分科会の3種類。同じ日に複数開くこともある）の後に、小山（開催者）が Teams の文字起こしを Box に置くと、議事録の作成・格納と、次回用の課題リストの格納までを Workato が自動で行う。
会議前の議題・課題リストの作成と格納、会議フォルダの作成、お知らせメールは担当者の手作業（自動化しない）。
本番運用の開始目標：2026年10月5日（月）
会議の開催者・レシピの担当者：小山　／　定例資料・議事録の担当：金子主任（AI が作った議事録と次回用の課題リストはたたき台。金子主任が確認して確定する）

利用者向けの説明は `manual/定例議事録・課題リスト運用マニュアル.docx`、この README は組み立てる人向けの手順。
運用マニュアルは社内向けの内容（Workato の構成、窓口・申請手順）を含むため、日建設計と共有している Box（901・902）には置かず、生産技術部の Teams（SharePoint）など社内だけの場所に置く。
Workato の開発・運用は、社内の Workato 開発マニュアル（実装編・API編・運用編）に従う。

## 全体の流れ

```
①会議前（担当者の手作業）
   Box 901 に会議フォルダ（YYMMDD_第NN回_{会議の種類}）を作って議題と課題リストを置き、関係者にお知らせメールを送る

②Teams で会議（録音・文字起こし）

③会議後（小山の手作業は1つだけ。キー払い出し後は自動化する）
   Teams から文字起こし（.vtt）をダウンロードし、会議の種類に合った受付（901/00_受付_{会議の種類}）に置く
      │ Box の Webhook でレシピ REC_定例議事録作成 が起動
      ▼
 文字起こしを会議フォルダへ移し、名前をそろえる
 議題・課題リスト・その種類の前回の未決事項を読み取り → LLM API（Claude など）が議事録データを作成
      │
      ├─ 議題ファイルに結果を書き込み、「議事録」として会議フォルダに格納（議題ファイルは元のまま残す）
      ├─ 議事録要約.md（課題リストへの赤字追記の文案つき）を会議フォルダに格納
      ├─ 最新_未決事項一覧_{会議の種類}.md を 901 で更新
      ├─ 宿題を ToDo リスト（椙山改修の Teams の「リスト」）に追加
      └─ 課題リスト（3種類の会議で共通の1つ。運用ルール⑤）：その日の最初の会議のあとに1回だけ、
         902 直下の課題リストを OLD へ移し、次回定例日の日付を付けた新しい課題リスト（全部黒字）を 902 に作る
      │
      ▼
 WowTalk に完了通知（リンク・要確認事項）

④AI アシスタント（Lightblue。別に作る、担当：小山）が 901・902 と図面リスト履歴を読み込み、質問に答える
```

## Box のフォルダとファイル名

```
椙山125WEST（Box）/
├── 900図面・計画書回覧フォルダ/（図面・計画書進捗管理の Workato が見張る。ここには何も置かない）
├── 901_総合定例会議資料/
│   ├── 00_受付_総合定例会議/（小山が文字起こし .vtt を置く）
│   ├── 00_受付_定例会議/（同上）
│   ├── 00_受付_分科会/（同上）
│   ├── 261002_第05回_総合定例会議/（毎回手で作る。担当は金子主任、名前の付け方を守れば誰が作ってもよい）
│   ├── 261002_第12回_定例会議/
│   │   ├── 261002_第12回_議題.xlsx（金子主任が作る）
│   │   ├── 261002_第12回_課題リスト.xlsx（金子主任がコピー。運用ルール②）
│   │   ├── 261002_第12回_議事録.xlsx（自動）
│   │   ├── 261002_第12回_議事録要約.md（自動）
│   │   └── 261002_第12回_文字起こし.vtt（自動で受付から移す）
│   ├── 261002_第03回_分科会/
│   ├── 最新_未決事項一覧_総合定例会議.md（自動で新しい版に更新）
│   ├── 最新_未決事項一覧_定例会議.md（同上）
│   └── 最新_未決事項一覧_分科会.md（同上）
└── 902_課題リスト/
    ├── 261009_課題リスト.xlsx（次回定例日の日付。3種類の会議で共通。直下は常に1つ）
    └── OLD/（確認が済んだ過去の課題リスト）
```

- **会議の種類**は「総合定例会議」「定例会議」「分科会」の3つ。いつどの会議を開くかは決まっていないので、会議フォルダは開くたびに手で作る。
- **会議フォルダ**は `YYMMDD_第NN回_{会議の種類}`（日付は開催日を6桁、回数は種類ごとに数えて2桁）。レシピは、文字起こしが置かれた受付の種類と日付で会議フォルダを見つける。中のファイルは、名前に「議題」「課題」を含む Excel を議題・課題リストとして探す。
- **課題リスト**は3種類の会議で共通の1つ。会議フォルダにコピーがなければ、902 直下のこの日の課題リスト（`YYMMDD_課題リスト.xlsx`）を読む。902 直下の課題リストの日付は**次回定例日**。
- **未決事項一覧**は会議の種類ごとに持つ（`最新_未決事項一覧_{会議の種類}.md`）。
- **1つの Teams 会議で2つの会議を続けて開くとき**：切り替えのときに文字起こしを止めて開始し直し、文字起こしを会議ごとに分ける。分けそこねて1つになったときは、同じ文字起こしを両方の受付に置く（AI は、その会議の議題に関係する部分だけで議事録を作る）。
- **無限ループの防止**（実装編「禁止事項」）：レシピが見張るのは3つの受付だけ。レシピは受付から文字起こしを移し、出力は受付の外にだけ置く。

## Workato の構成

実装編の命名規則（`アセットコード_名称`、名称に `_` を使わない）とフォルダの付け方に従う。図面・計画書進捗管理と同じプロジェクトに入れる。

```
[E○○○]名古屋支店_生産技術部
└── 01. 生産推進G
    ├── 01. 図面・計画書進捗管理
    └── 02. 定例議事録作成
        ├── 00. 共通      ← レシピ REC_定例議事録作成
        └── 01. 椙山改修  ← 工事設定（Box のフォルダ、SharePoint の作業場所、WowTalk の送り先）
```

| 種類 | 名前 | 役割 |
|---|---|---|
| レシピ | `REC_定例議事録作成` | 文字起こしが受付に置かれたら、議事録・議事録要約・未決事項一覧・次回用の課題リストを作って格納し、WowTalk に通知 |
| コネクション | `CON-RW_椙山改修Box`（図面・計画書進捗管理と共用） | Box のファイルの取得・格納・移動、3つの受付の Webhook |
| コネクション | `CON-RW_椙山改修SharePoint`（同上） | 作業用の Excel の置き場所。Microsoft Graph の Excel 操作（workbook API）で読み書きする。ToDo リストへの追加 |
| コネクション | LLM API（AI推進G のカスタムコネクタ。名前は利用マニュアルに従う） | 文字起こしから議事録データを作る |
| ルックアップテーブル | 工事設定・受付設定（アセットコードは実装編 p.15 の一覧に従う） | 下の表の項目 |
| 共通レシピ | wowtalkチャット送信、エラー通知（B001） | 完了通知とエラー通知 |

工事設定（椙山改修の行）：

| 項目 | 値の例 |
|---|---|
| 工事名 | 椙山改修 |
| 定例資料フォルダID | `901_総合定例会議資料` の Box フォルダ ID |
| 課題リストフォルダID | `902_課題リスト` の Box フォルダ ID |
| 課題リストOLDフォルダID | `902_課題リスト/OLD` の Box フォルダ ID |
| SharePointサイトID・作業フォルダ | 椙山改修の Teams（SharePoint）サイトと、その中の作業用フォルダ（例：`定例議事録作業`） |
| WowTalk送り先 | 完了通知を送るトーク（議事録の担当者・レシピの担当者が入っているもの） |
| ToDoリスト | 椙山改修の Teams に作った「リスト」（SharePoint のリスト）の名前 |

受付設定（受付フォルダ1つにつき1行。3行）：

| 受付フォルダID | 工事名 | 会議の種類 |
|---|---|---|
| `901_総合定例会議資料/00_受付_総合定例会議` の ID | 椙山改修 | 総合定例会議 |
| `901_総合定例会議資料/00_受付_定例会議` の ID | 椙山改修 | 定例会議 |
| `901_総合定例会議資料/00_受付_分科会` の ID | 椙山改修 | 分科会 |

Pythonスニペット（`workato/python/`）はレシピの中に貼り付けて使う。どれも標準ライブラリだけで動く。

| ファイル | 役割 |
|---|---|
| `p1a_find_meeting.py` | 受付の種類と、文字起こしの名前か置いた日から、901 の会議フォルダ（YYMMDD_第NN回_{会議の種類}）を探す |
| `p1b_find_files.py` | 会議フォルダの中の議題・課題リストを探す（課題リストがなければ 902 直下のこの日のものを使う）。同じ会議の文字起こしが複数あれば、つなげる順番を決める |
| `p2_vtt_to_text.py` | Teams の .vtt を「話者：発言」の形に整える（複数あれば時刻の順につなげる） |
| `p3_read_agenda.py` | 議題ファイル（A1:AN120 の表示文字列）から議題No・本文・参加者名簿・開催情報を読む |
| `p4_read_issues.py` | 課題リスト（使用範囲の表示文字列）から課題No・概要・経過・期限を読む |
| `p5_build_writes.py` | LLM の回答から、議題ファイルに書き込むセルと値（結果欄・表題「第N回　{会議の種類}議事録」・出席チェック・次回開催）、議事録要約、次回定例日を作る |
| `p6_issue_plan.py` | 次回用の課題リストを作るかどうかを決める（同じ日の最初の会議のあとに1回だけ） |
| `p7_build_todos.py` | LLM の回答の宿題から、ToDo リストに追加する行を作る（作り直しても二重に登録しないキー付き） |

## レシピ REC_定例議事録作成

Graph の呼び出しは、SharePoint コネクションのカスタムアクション（図面リストへの書き込みと同じ方法）で行う。`{ブック}` は `/sites/{サイトID}/drive/items/{作業ファイルのID}/workbook`。

**レシピの設定で「同時実行数」を 1 にする。** 同じ日に3種類の会議があり、文字起こしが続けて置かれても、1件ずつ順に処理する。録音・文字起こしが途中で止められて文字起こしが分かれた場合は、先の実行が同じ会議の文字起こしをまとめてつなげて移し、後の実行は `already_processed` で何もせずに終わる。あとから追加されたときは、その会議の全部の文字起こしで議事録を作り直す（新しい版として上書き）。

| # | アクション | 設定・ポイント |
|---|---|---|
| T | トリガー：Box「フォルダに新しいファイル」 | 3つの受付フォルダ。Box の Webhook に3つとも追加する |
| 1 | ルックアップテーブル：受付設定 → 工事設定を検索 | 受付フォルダID から会議の種類と工事を引く |
| 2 | 条件 | 拡張子が `.vtt` でなければ、WowTalk に「文字起こしは .vtt でダウンロードして置き直してください」と通知して終了（ファイルは受付に残す） |
| 3 | Box：フォルダ内の一覧 ×2（その受付・定例資料フォルダ直下） → Python `p1a_find_meeting` | `meeting_type` に会議の種類を渡す。一覧の id・name・created_at（直下は type も）を JSON にして渡す。`already_processed` が true なら何もせず終了。`found` が false なら、ログを WowTalk に通知して終了（ファイルは受付に残す） |
| 3b | Box：会議フォルダ内の一覧、課題リストフォルダ直下の一覧 → Python `p1b_find_files` | `found` が false なら、ログを WowTalk に通知して終了 |
| 4 | 繰り返し（`combine` の各要素）：Box：ファイルのダウンロード → 中身を配列に集める → Python `p2_vtt_to_text` | `vtts` に配列を JSON にして渡す |
| 5 | 繰り返し（`combine` のうち `in_inbox` が true のもの）：Box：ファイルの移動・名前の変更 | 会議フォルダへ、名前を `new_name` に（**受付の外へ出す**） |
| 6 | Box：議題をダウンロード → SharePoint：作業フォルダにアップロード | 名前 `{meeting_date}_{会議の種類}_議題.xlsx` |
| 7 | Graph `GET {ブック}/worksheets?$select=name,position` | position 0 のシート名を覚える（議事録フォーマットは「打合せ記録 」と末尾に空白がある） |
| 8 | Graph `GET {ブック}/worksheets('{シート名}')/range(address='A1:AN120')?$select=text` → Python `p3_read_agenda` | `values` に `text` を JSON にして渡す |
| 9 | 課題リストがあるとき：Box からダウンロード → SharePoint にアップロード → Graph `GET {ブック}/worksheets('課題リスト')/usedRange(valuesOnly=true)?$select=address,text` → Python `p4_read_issues` | 名前 `{meeting_date}_{会議の種類}_課題リスト.xlsx`。ないときは `issues_json` を `[]` とする |
| 10 | Box：`最新_未決事項一覧_{会議の種類}.md` をダウンロード | ないとき（その種類の初回）は「なし」 |
| 11 | LLM API：テキスト生成 | プロンプトは `prompts/01_議事録作成プロンプト.md`。開催情報に会議の種類を入れる。長い文字起こしを扱えるモデル（Claude など）を選ぶ |
| 12 | Python `p5_build_writes` | `values` は手順8と同じもの。`meeting_type` に会議の種類。`ok` が false なら、ログを WowTalk に通知して終了 |
| 13 | 繰り返し（`writes` の各要素） → Graph `PATCH {ブック}/worksheets('{シート名}')/range(address='{address}')` | 本文 `{"values": {values}}` |
| 14 | SharePoint：議題の作業ファイルをダウンロード → Box：アップロード | 会議フォルダに `{meeting_date}_第{number}回_議事録.xlsx`（`minutes_exists` のときは新しい版としてアップロード） |
| 15 | Box：アップロード ×2 | 会議フォルダに `{meeting_date}_第{number}回_議事録要約.md`（`markdown`）、定例資料フォルダ直下に `最新_未決事項一覧_{会議の種類}.md`（`open_items_markdown`）。どちらも、あれば新しい版としてアップロード |
| 16 | 課題リストがあるとき：Box：課題リストフォルダ直下の一覧 → Python `p6_issue_plan` | `move_id` があれば OLD へ移動（運用ルール⑤）。`create_next` が false なら 17〜19 を飛ばす |
| 17 | 同上：Graph `PATCH {ブック}/worksheets('課題リスト')/range(address='A7:P{last_row}')/format/font` | 本文 `{"color": "#000000"}`（全部黒字に戻す） |
| 18 | 同上：Graph `PATCH {ブック}/worksheets('課題リスト')/range(address='O1')` | 本文 `{"values": [["{次回定例日 YYYY/M/D}"]]}` |
| 19 | 同上：SharePoint：課題リストの作業ファイルをダウンロード → Box：アップロード | 課題リストフォルダに `{next_meeting_file_date}_課題リスト.xlsx` |
| 19b | Python `p7_build_todos` → 繰り返し（`todos` の各要素）：SharePoint「リスト項目の検索」（キー列が同じ行）→ なければ「リスト項目の作成」 | `minutes_url` は手順14でアップロードした議事録の Box のリンク。列の対応は下の「ToDo リスト」 |
| 20 | 共通レシピ：wowtalkチャット送信 | 「{会議の種類} 第{回}回 議事録を格納しました」＋ Box のリンク＋ `log`（名簿にない参加者、結果欄の不足、次回定例日を7日後にした、次回用の課題リストは作成済み など）＋ 議事録要約の「※要確認」の件数 |
| 21 | SharePoint：作業ファイルを削除 | 議題・課題リストの2つ |
| E | エラー時（Monitor ブロック） | 共通レシピ：エラー通知。文字起こしが受付に残っていれば、置き直すだけでやり直せる |

## ToDo リスト（Teams の「リスト」）

椙山改修の Teams のチャネルに「リスト」（Microsoft Lists）で作る。列は次のとおり（列の名前を変えたら、手順19b の対応も合わせる）。

| 列 | 種類 | 中身 | 入れる人 |
|---|---|---|---|
| タイトル（内容） | 1行テキスト | 宿題の中身 | 自動（`title`） |
| 担当 | 1行テキスト | NS・SC・氏名 | 自動（`owner`） |
| 期限 | 日付 | 会議で話された期限（なければ空） | 自動（`due`） |
| 状態 | 選択肢（未着手／対応中／完了。既定値は未着手） | 進み具合 | 人 |
| 会議 | 1行テキスト | 例：定例会議 第12回（261002） | 自動（`meeting`） |
| 議題No | 1行テキスト | 例：No.3、議題外：搬入経路の変更 | 自動（`agenda_no`） |
| 議事録 | ハイパーリンク | Box の議事録へのリンク | 自動（`minutes_url`） |
| キー | 1行テキスト（一覧では非表示にしてよい） | 二重登録を防ぐための値 | 自動（`key`） |

- 状態は人が更新する。レシピは、同じキーの行がすでにあれば何もしない（議事録を作り直しても、状態は上書きされない）。
- 期限切れは、リストのビューで「期限が今日より前、かつ状態が完了以外」で絞り込み、色分けする。
- 椙山改修の Teams には日建設計がゲストで入っているので、ToDo リストは日建設計からも見える。

## 文字起こしの自動取得（キー払い出し後に追加）

Teams の文字起こしを Microsoft Graph から取り出すキーを、小山が窓口に申請する（依頼文は `workato/窓口依頼_文字起こしキー.md`）。払い出されたら次のレシピを追加し、受付に置く手作業をなくす。既存の `REC_定例議事録作成` は変更しない。

会議の日程は決まっていないので、小山の予定表から会議を探す。Teams の会議の件名に、会議の種類（総合定例会議／定例会議／分科会）を入れておく。
Teams の会議を分けられず、1つの会議で続けて開く日（例：定例会議のあとに分科会）は、件名に**開く順に**種類を書く（例：「椙山 定例会議・分科会」）。切り替えのときに文字起こしを止めて開始し直すので、文字起こしは会議の数だけに分かれる。

| # | アクション | 設定・ポイント |
|---|---|---|
| T | トリガー：スケジュール | 平日の夕方（例：17:00・18:00・19:00 の3回）。会議が延びても拾えるようにする |
| 1 | HTTP（Microsoft Graph、小山のアカウントの委任アクセス） `GET /me/calendarView?startDateTime={今日0時}&endDateTime={今日24時}` | 件名に「椙山」と会議の種類を含み、Teams 会議（`onlineMeeting.joinUrl` あり）の予定だけ残す |
| 2 | 繰り返し（予定ごと）：`GET /me/onlineMeetings?$filter=JoinWebUrl eq '{joinUrl}'` → `GET /me/onlineMeetings/{会議ID}/transcripts` | |
| 3 | データテーブル「取得済み文字起こし」と照合 | まだ取得していない文字起こし ID だけを残す（二重に格納しないため） |
| 4 | 繰り返し：`GET /me/onlineMeetings/{会議ID}/transcripts/{ID}/content?$format=text/vtt` → Box：アップロード | 件名に種類が1つなら、その種類の受付に。件名に種類が複数あれば、文字起こしを createdDateTime の早い順に並べ、件名の順の受付に1つずつ置く（文字起こしの数が種類の数と合わないときは、全部を件名の最初の種類の受付に置き、WowTalk で小山に知らせる）。名前は `{createdDateTime を日本時間にした YYMMDD}_{会議の種類}_文字起こし_{文字起こしIDの末尾6文字}.vtt`（先頭の日付で p1a が開催日を決める） |
| 5 | データテーブルに文字起こし ID を記録 | |
| E | エラー時 | 共通レシピ：エラー通知。取得できなかったときは、従来どおり小山が手で受付に置けばよい |
