# 椙山改修 定例会議 議事録・課題リスト自動格納システム（構築手順）

Teams 定例（録音・文字起こし）が終わったら、議事録の作成・格納と、次回用の課題リストの格納までを自動で行う。
定例前の議題・課題リストの作成と格納、お知らせメールは担当者の手作業（自動化しない）。
利用者向けの説明は `manual/定例会議_議事録自動化_運用マニュアル.docx`、この README は組み立てる人向けの手順。

## 全体の流れ

```
①定例前（担当者の手作業。自動化しない）
   担当者が Box の中で議題と課題リストを作り、010_定例打合せ議事録 に格納して、関係者にお知らせメールを送る

②Teams 定例会議（自動で録音・文字起こし）
      │ 議事録作成フロー（会議終了の30分後に自動で開始）
      ▼
 文字起こし → Box 020_文字起こし
 Box の議題・課題リスト・前回の未決事項を読み取り → AI が議事録データを作成
      │
      ├─ 議題ファイルに結果を書き込み、名前を「議事録」に変えて Box 010 に格納（議題ファイルは元のまま残す）
      ├─ 議事録要約.md（AI 用の本文、課題リストへの赤字追記の文案つき）を Box 010 に格納
      ├─ 最新_未決事項一覧.md を Box 030 に上書き
      └─ 課題リスト（運用ルール⑤）：000 直下の課題リストを OLD へ移し、
         次回定例日の日付を付けた新しい課題リスト（全部黒字）を 000 に作る
      │
      ▼
 Teams チャネルに完了通知（リンク・要確認事項）

③Box AI Hub が 000・010・030・090 と図面リスト履歴を読み込み、質問に答える
```

## Box のフォルダとファイル名

```
椙山改修_定例会議/
├── 000_課題リスト/        20261016_課題リスト.xlsx（次回定例日の日付。直下は常に1つ）
│   └── OLD/               確認が済んだ過去の課題リスト
├── 010_定例打合せ議事録/  20261002_第02回_議題.xlsx          ← 担当者が作成
│                          20261002_第02回_課題リスト.xlsx    ← 担当者がコピー（運用ルール②）
│                          20261002_第02回_議事録.xlsx        ← 自動
│                          20261002_第02回_議事録要約.md      ← 自動
├── 020_文字起こし/        20261002_第02回_文字起こし.vtt     ← 自動
├── 030_最新状況/          最新_未決事項一覧.md               ← 自動（上書き）
└── 090_運用マニュアル/    運用マニュアル、図面・計画書進捗管理 運用マニュアル
```

- 010 のファイル名の日付は**その定例の開催日**（YYYYMMDD）、回数は2桁（第02回）。議事録作成フローはこの名前でファイルを探すので、**担当者はこのルールで名前を付ける**。
- 000 直下の課題リストの日付は**次回定例日**（125WEST の運用ルール①と同じ）。
- **置き場所の注意**：`椙山125WEST【社外共有02】他社設計 > 900図面・計画書回覧フォルダ` の中には作らない。Workato がこのフォルダを見張っていて、ファイル名の図面名・整理番号から図面リストに日付を記入するため。

## 事前準備（最初に1回だけ）

### 1. Teams：会議を自動で録音・文字起こしする
定例会議の予定を開き、**会議のオプション**で「自動的に録音する」「文字起こしを自動で開始する」をオンにする（開催者が設定）。

### 2. Entra ID：文字起こしを取得するアプリを登録する（IT 管理者に依頼）

| 項目 | 設定 |
|---|---|
| API のアクセス許可（アプリケーション） | `OnlineMeetings.Read.All`、`OnlineMeetingTranscript.Read.All`、`Calendars.Read` ＋管理者の同意 |
| クライアントシークレット | 発行し、Power Automate の HTTP アクションで使う |
| アプリケーション アクセス ポリシー | Teams PowerShell で開催者に付与する（下記） |

```powershell
New-CsApplicationAccessPolicy -Identity "Sugiyama-Minutes" -AppIds "<アプリID>" -Description "椙山改修 議事録自動化"
Grant-CsApplicationAccessPolicy -PolicyName "Sugiyama-Minutes" -Identity "<開催者のメールアドレス>"
```

> アプリ登録ができない場合は「方式B（半自動）」で運用できる。

### 3. SharePoint：作業用フォルダを作る
Office Scripts は OneDrive か SharePoint 上のブックにしか実行できないため、作業用フォルダ（例：`椙山改修/_作業用`）を用意する。

### 4. Office Scripts を登録する
Excel on the web の **自動化 → 新しいスクリプト** で次の4本を作る。

| スクリプト名 | 貼り付ける内容 | 役割 |
|---|---|---|
| `readAgenda` | `office-scripts/readAgenda.ts` | 議題ファイルから議題No・本文・参加者名簿を読む |
| `readIssues` | `office-scripts/readIssues.ts` | 課題リストから課題No・概要・経過・期限を読む |
| `fillMinutes` | `office-scripts/fillMinutes.ts` | AI の結果を議題ファイルに書き込む（結果欄・日時・出席チェック・次回開催） |
| `prepareNextIssues` | `office-scripts/prepareNextIssues.ts` | 次回用の課題リストを作る（全部黒字に戻し、定例日を次回定例日にする） |

### 5. AI Builder のプロンプトを作る
Power Automate → AI ハブ → **プロンプト** で新規作成し、`prompts/01_議事録作成プロンプト.md` の本文を貼り付ける。
入力は `議題JSON`・`課題リストJSON`・`開催情報`・`前回までの未決事項`・`文字起こし` の5つ、出力は **JSON**。

### 6. Box のフォルダを作る
上の「Box のフォルダとファイル名」のとおりに作る。

### 7. Box AI Hub を作る
`boxai/アシスタント設定.md` のとおりに作る。

### 8. 議事録フォーマット
`議事録フォーマット_修正版4.xlsx` を議題づくりの元にする（名簿の出席チェックボックスは非表示の AM 列＝現地、AN 列＝WEB にリンク済み）。AM・AN 列は非表示のままにし、名簿の行・列を挿入・削除しない。

## 定例前（自動化しない）
議題・課題リストの作成と Box への格納、お知らせメールは担当者が手作業で行う。議事録作成フローが見つけられるよう、010 のファイル名だけはルールどおりにする。

## 議事録作成フロー：定例終了 → 議事録・課題リストの格納

| # | アクション | 設定・ポイント |
|---|---|---|
| 1 | トリガー：Outlook「今後のイベントがまもなく開始されるとき (V3)」 | 定例用の予定表。条件：件名に `椙山` と `定例` を含む |
| 2 | 待ち時間 | 終了時刻＋30分まで（文字起こしの生成待ち） |
| 3 | Box「フォルダー内のファイルを一覧表示」 | `010_定例打合せ議事録` から `{開催日}_第NN回_議題.xlsx` と `{開催日}_第NN回_課題リスト.xlsx` を探し、回数を取り出す。議題がなければ回数は空で続行し、手順17で「議題なし」と通知 |
| 4 | HTTP：トークン取得 | `POST https://login.microsoftonline.com/{tenant}/oauth2/v2.0/token`（client_credentials、scope=`https://graph.microsoft.com/.default`） |
| 5 | HTTP：会議の参加 URL | `GET /v1.0/users/{開催者}/events/{イベントID}?$select=onlineMeeting` |
| 6 | HTTP：会議 ID | `GET /v1.0/users/{開催者}/onlineMeetings?$filter=JoinWebUrl eq '{joinUrl}'` |
| 7 | HTTP：文字起こしの一覧 → 本文 | `GET …/onlineMeetings/{会議ID}/transcripts` の最新1件 → `GET …/transcripts/{ID}/content?$format=text/vtt` |
| 8 | Box「ファイルの作成」 | `020_文字起こし/{日付}_第{回}回_文字起こし.vtt` |
| 9 | Box「ファイルコンテンツの取得」→ SharePoint「ファイルの作成」×2 | 議題と課題リストを `_作業用/{日付}_議題.xlsx`・`_作業用/{日付}_課題リスト.xlsx` にコピー（Office Scripts は SharePoint 上のブックにしか実行できないため） |
| 10 | Excel Online「スクリプトの実行」 | `_作業用/{日付}_議題.xlsx` に `readAgenda` |
| 11 | Excel Online「スクリプトの実行」 | `_作業用/{日付}_課題リスト.xlsx` に `readIssues`（ファイルがなければ `[]`） |
| 12 | Box「パスを使用してファイルコンテンツを取得」 | `030_最新状況/最新_未決事項一覧.md`（初回はないので失敗時も続行し「なし」を渡す） |
| 13 | AI Builder「プロンプトを実行する」 → 「JSON の解析」 | 手順10・11・12・7の結果と開催情報を渡す |
| 14 | Excel Online「スクリプトの実行」 | `_作業用/{日付}_議題.xlsx` に `fillMinutes`（`minutesJson`＝手順13の出力）。戻り値が `OK` 以外なら手順17で通知 |
| 15a | SharePoint「ファイル コンテンツの取得」→ Box「ファイルの作成」 | `010_定例打合せ議事録/{日付}_第{回}回_議事録.xlsx`（**議題.xlsx は元のまま残す**） |
| 15b | Box「ファイルの作成」 | `010_定例打合せ議事録/{日付}_第{回}回_議事録要約.md`（`markdown`） |
| 15c | Box「ファイルの更新」または「作成」 | `030_最新状況/最新_未決事項一覧.md`（`open_items_markdown`、上書き） |
| 16a | 次回定例日を決める | AI の `next_meeting.date`。空なら Outlook「イベントのカレンダー ビューを取得 (V3)」で、今日より後の最初の「椙山」「定例」の予定の日付。どちらもなければ 16b〜16d を飛ばし、手順17で「次回定例日が分からないため課題リストを作っていません」と通知 |
| 16b | Box「フォルダー内のファイルを一覧表示」→「ファイルのコピー」→「ファイルの削除」 | `000_課題リスト` 直下の課題リストを `OLD` へ移す（運用ルール⑤） |
| 16c | Excel Online「スクリプトの実行」 | `_作業用/{日付}_課題リスト.xlsx` に `prepareNextIssues`（`nextMeetingDate`＝16a の日付）。全部黒字に戻し、O1 を次回定例日にする |
| 16d | SharePoint「ファイル コンテンツの取得」→ Box「ファイルの作成」 | `000_課題リスト/{次回定例日}_課題リスト.xlsx` |
| 17 | Teams「チャネルにメッセージを投稿」 | 「第{回}回 議事録と次回の課題リストを格納しました」＋リンク＋スクリプトのログ＋要確認事項（※要確認、名簿にない参加者、議題なし など） |
| 18 | SharePoint「ファイルの削除」 | `_作業用` の2つのファイルを消す |

### 方式B（半自動）：アプリ登録ができない場合
手順4〜7の代わりに、開催者が定例後に Teams の「レコーディングと文字起こし」から文字起こし（.vtt または .docx）をダウンロードし、Box `020_文字起こし` に `{日付}_第{回}回_文字起こし.vtt` の名前で置く。
議事録作成フローのトリガーを Box「フォルダーにファイルが作成されたとき」（`020_文字起こし`）にすれば、手順9以降は同じ。

## 動作確認
- `samples/sample_ai_output.json` は AI の出力例。議題ファイルのコピーに `fillMinutes` を実行するときにこの JSON を渡すと、書き込み位置を確認できる。
- 本番前に、テスト用の議題（`{日付}_第99回_議題.xlsx`）と課題リストを 010 に置き、短い Teams 会議（件名に「椙山」「定例」）で議事録作成フローを通しで1回動かす。
