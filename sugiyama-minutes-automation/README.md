# 椙山改修 定例会議 議事録・課題リスト自動格納システム（構築手順・Workato 版）

定例後に小山（開催者）が Teams の文字起こしを Box に置くと、議事録の作成・格納と、次回用の課題リストの格納までを Workato が自動で行う。
定例前の議題・課題リストの作成と格納、お知らせメールは担当者の手作業（自動化しない）。
定例の開催者・レシピの担当者：小山　／　定例資料・議事録の担当：金子主任（AI が作った議事録と次回用の課題リストはたたき台。金子主任が確認して確定する）

利用者向けの説明は `manual/定例会議_議事録自動化_運用マニュアル.docx`、この README は組み立てる人向けの手順。
運用マニュアルは社内向けの内容（Workato の構成、窓口・申請手順）を含むため、日建設計と共有している Box（901・902）には置かず、生産技術部の Teams（SharePoint）など社内だけの場所に置く。
Workato の開発・運用は、社内の Workato 開発マニュアル（実装編・API編・運用編）に従う。

## 全体の流れ

```
①定例前（担当者の手作業）
   Box 901 に定例フォルダ（YYMMDD_第NN回_定例会議）を作って議題と課題リストを置き、関係者にお知らせメールを送る

②Teams 定例会議（録音・文字起こし）

③定例後（小山の手作業は1つだけ。キー払い出し後は自動化する）
   Teams から文字起こし（.vtt）をダウンロードし、Box 901/00_受付 に置く
      │ Box の Webhook でレシピ REC_定例議事録作成 が起動
      ▼
 文字起こしを定例フォルダへ移し、名前をそろえる
 Box の議題・課題リスト・前回の未決事項を読み取り → LLM API（Claude など）が議事録データを作成
      │
      ├─ 議題ファイルに結果を書き込み、「議事録」として定例フォルダに格納（議題ファイルは元のまま残す）
      ├─ 議事録要約.md（課題リストへの赤字追記の文案つき）を定例フォルダに格納
      ├─ 最新_未決事項一覧.md を 901 で更新
      └─ 課題リスト（運用ルール⑤）：902 直下の課題リストを OLD へ移し、
         次回定例日の日付を付けた新しい課題リスト（全部黒字）を 902 に作る
      │
      ▼
 WowTalk に完了通知（リンク・要確認事項）

④AI アシスタント（Lightblue。別に作る、担当：小山）が 901・902 と図面リスト履歴を読み込み、質問に答える
```

## Box のフォルダとファイル名

```
椙山125WEST（Box）/
├── 900図面・計画書回覧フォルダ/（図面・計画書進捗管理の Workato が見張る。ここには何も置かない）
├── 901_総合定例会議資料/
│   ├── 00_受付/（小山が文字起こし .vtt を置く。レシピはここだけを見張る）
│   ├── 261002_第02回_定例会議/（毎回手で作る。担当は金子主任、名前の付け方を守れば誰が作ってもよい）
│   │   ├── 261002_第02回_議題.xlsx（金子主任が作る）
│   │   ├── 261002_第02回_課題リスト.xlsx（金子主任がコピー。運用ルール②）
│   │   ├── 261002_第02回_議事録.xlsx（自動）
│   │   ├── 261002_第02回_議事録要約.md（自動）
│   │   └── 261002_第02回_文字起こし.vtt（自動で受付から移す）
│   └── 最新_未決事項一覧.md（自動で新しい版に更新）
└── 902_課題リスト/
    ├── 261016_課題リスト.xlsx（次回定例日の日付。直下は常に1つ）
    └── OLD/（確認が済んだ過去の課題リスト）
```

- **定例フォルダ**は `YYMMDD_第NN回_定例会議`（日付はその定例の開催日を6桁、回数は2桁）。レシピはこのフォルダ名で回を見つける。中のファイルは、名前に「議題」「課題」を含む Excel を議題・課題リストとして探す（名前は `YYMMDD_第NN回_議題.xlsx` などにそろえることを推奨）。
- 902 直下の課題リストの日付は**次回定例日**（125WEST の運用ルール①と同じ）。
- **無限ループの防止**（実装編「禁止事項」）：レシピが見張るのは `00_受付` だけ。レシピは受付から文字起こしを移し、出力は受付の外にだけ置く。

## Workato の構成

実装編の命名規則（`アセットコード_名称`、名称に `_` を使わない）とフォルダの付け方に従う。図面・計画書進捗管理と同じプロジェクトに入れる。

```
[E○○○]名古屋支店_生産技術部
└── 01. 生産推進G
    ├── 01. 図面・計画書進捗管理
    └── 02. 定例議事録作成
        ├── 00. 共通      ← レシピ REC_定例議事録作成
        └── 01. 椙山改修  ← 工事設定（Box のフォルダ、SharePoint の作業場所、WowTalk の送り先）
```

| 種類 | 名前 | 役割 |
|---|---|---|
| レシピ | `REC_定例議事録作成` | 文字起こしが 00_受付 に置かれたら、議事録・議事録要約・未決事項一覧・次回用の課題リストを作って格納し、WowTalk に通知 |
| コネクション | `CON-RW_椙山改修Box`（図面・計画書進捗管理と共用） | Box のファイルの取得・格納・移動、00_受付 の Webhook |
| コネクション | `CON-RW_椙山改修SharePoint`（同上） | 作業用の Excel の置き場所。Microsoft Graph の Excel 操作（workbook API）で読み書きする |
| コネクション | LLM API（AI推進G のカスタムコネクタ。名前は利用マニュアルに従う） | 文字起こしから議事録データを作る |
| ルックアップテーブル | 工事設定（アセットコードは実装編 p.15 の一覧に従う） | 1行＝1工事。下の表の項目 |
| 共通レシピ | wowtalkチャット送信、エラー通知（B001） | 完了通知とエラー通知 |

工事設定（椙山改修の行）：

| 項目 | 値の例 |
|---|---|
| 工事名 | 椙山改修 |
| 受付フォルダID | `901_総合定例会議資料/00_受付` の Box フォルダ ID |
| 定例資料フォルダID | `901_総合定例会議資料` の Box フォルダ ID |
| 課題リストフォルダID | `902_課題リスト` の Box フォルダ ID |
| 課題リストOLDフォルダID | `902_課題リスト/OLD` の Box フォルダ ID |
| SharePointサイトID・作業フォルダ | 椙山改修の Teams（SharePoint）サイトと、その中の作業用フォルダ（例：`定例議事録作業`） |
| WowTalk送り先 | 完了通知を送るトーク（議事録の担当者・レシピの担当者が入っているもの） |

Pythonスニペット（`workato/python/`）はレシピの中に貼り付けて使う。どれも標準ライブラリだけで動く。

| ファイル | 役割 |
|---|---|
| `p1a_find_meeting.py` | 文字起こしの名前か置いた日から開催日を決め、901 の定例フォルダ（YYMMDD_第NN回_定例会議）を探す |
| `p1b_find_files.py` | 定例フォルダの中の議題・課題リストを探す。同じ日の文字起こしが複数あれば、つなげる順番を決める |
| `p2_vtt_to_text.py` | Teams の .vtt を「話者：発言」の形に整える（複数あれば時刻の順につなげる） |
| `p3_read_agenda.py` | 議題ファイル（A1:AN120 の表示文字列）から議題No・本文・参加者名簿・開催情報を読む |
| `p4_read_issues.py` | 課題リスト（使用範囲の表示文字列）から課題No・概要・経過・期限を読む |
| `p5_build_writes.py` | LLM の回答から、議題ファイルに書き込むセルと値（結果欄・表題・出席チェック・次回開催）、議事録要約、次回定例日を作る |

## レシピ REC_定例議事録作成

Graph の呼び出しは、SharePoint コネクションのカスタムアクション（図面リストへの書き込みと同じ方法）で行う。`{ブック}` は `/sites/{サイトID}/drive/items/{作業ファイルのID}/workbook`。

**レシピの設定で「同時実行数」を 1 にする。** 定例中に録音・文字起こしが止められると文字起こしが複数に分かれ、00_受付 に同時に置かれることがある。同時実行数 1 なら、先の実行が同じ日の文字起こしをまとめてつなげて移し、後の実行は `already_processed` で何もせずに終わる。あとから追加されたときは、その日の全部の文字起こしで議事録を作り直す（新しい版として上書き）。

| # | アクション | 設定・ポイント |
|---|---|---|
| T | トリガー：Box「フォルダに新しいファイル」 | 工事設定の受付フォルダ。Box の Webhook に受付フォルダを追加する |
| 1 | ルックアップテーブル：工事設定を検索 | 受付フォルダID で検索 |
| 2 | 条件 | 拡張子が `.vtt` でなければ、WowTalk に「文字起こしは .vtt でダウンロードして置き直してください」と通知して終了（ファイルは受付に残す） |
| 3 | Box：フォルダ内の一覧 ×2（受付・定例資料フォルダ直下） → Python `p1a_find_meeting` | 一覧の id・name・created_at（直下は type も）を JSON にして渡す。`already_processed` が true なら何もせず終了。`found` が false なら、ログを WowTalk に通知して終了（ファイルは受付に残す） |
| 3b | Box：定例フォルダ内の一覧 → Python `p1b_find_files` | `found` が false なら、ログを WowTalk に通知して終了 |
| 4 | 繰り返し（`combine` の各要素）：Box：ファイルのダウンロード → 中身を配列に集める → Python `p2_vtt_to_text` | `vtts` に配列を JSON にして渡す |
| 5 | 繰り返し（`combine` のうち `in_inbox` が true のもの）：Box：ファイルの移動・名前の変更 | 定例フォルダへ、名前を `new_name` に（**受付の外へ出す**） |
| 6 | Box：議題をダウンロード → SharePoint：作業フォルダにアップロード | 名前 `{meeting_date}_議題.xlsx` |
| 7 | Graph `GET {ブック}/worksheets?$select=name,position` | position 0 のシート名を覚える（議事録フォーマットは「打合せ記録 」と末尾に空白がある） |
| 8 | Graph `GET {ブック}/worksheets('{シート名}')/range(address='A1:AN120')?$select=text` → Python `p3_read_agenda` | `values` に `text` を JSON にして渡す |
| 9 | 課題リストがあるとき：Box からダウンロード → SharePoint にアップロード → Graph `GET {ブック}/worksheets('課題リスト')/usedRange(valuesOnly=true)?$select=address,text` → Python `p4_read_issues` | 名前 `{meeting_date}_課題リスト.xlsx`。ないときは `issues_json` を `[]` とする |
| 10 | Box：`最新_未決事項一覧.md` をダウンロード | ないとき（初回）は「なし」 |
| 11 | LLM API：テキスト生成 | プロンプトは `prompts/01_議事録作成プロンプト.md`。長い文字起こしを扱えるモデル（Claude など）を選ぶ |
| 12 | Python `p5_build_writes` | `values` は手順8と同じもの。`ok` が false なら、ログを WowTalk に通知して終了 |
| 13 | 繰り返し（`writes` の各要素） → Graph `PATCH {ブック}/worksheets('{シート名}')/range(address='{address}')` | 本文 `{"values": {values}}` |
| 14 | SharePoint：議題の作業ファイルをダウンロード → Box：アップロード | 定例フォルダに `{meeting_date}_第{number}回_議事録.xlsx`（`minutes_exists` のときは新しい版としてアップロード） |
| 15 | Box：アップロード ×2 | 定例フォルダに `{meeting_date}_第{number}回_議事録要約.md`（`markdown`）、定例資料フォルダ直下に `最新_未決事項一覧.md`（`open_items_markdown`）。どちらも、あれば新しい版としてアップロード |
| 16 | 課題リストがあるとき：Box：課題リストフォルダ直下の `{meeting_date}_課題リスト.xlsx` を OLD へ移動 | 運用ルール⑤。作り直しのときはすでに移してあるので、なければ飛ばす |
| 17 | 同上：Graph `PATCH {ブック}/worksheets('課題リスト')/range(address='A7:P{last_row}')/format/font` | 本文 `{"color": "#000000"}`（全部黒字に戻す） |
| 18 | 同上：Graph `PATCH {ブック}/worksheets('課題リスト')/range(address='O1')` | 本文 `{"values": [["{次回定例日 YYYY/M/D}"]]}` |
| 19 | 同上：SharePoint：課題リストの作業ファイルをダウンロード → Box：アップロード | 課題リストフォルダに `{next_meeting_file_date}_課題リスト.xlsx`（あれば新しい版としてアップロード） |
| 20 | 共通レシピ：wowtalkチャット送信 | 「第{回}回 議事録と次回の課題リストを格納しました」＋ Box のリンク＋ `log`（名簿にない参加者、結果欄の不足、次回定例日を7日後にした など）＋ 議事録要約の「※要確認」の件数 |
| 21 | SharePoint：作業ファイルを削除 | 議題・課題リストの2つ |
| E | エラー時（Monitor ブロック） | 共通レシピ：エラー通知。文字起こしが受付に残っていれば、置き直すだけでやり直せる |

## 文字起こしの自動取得（キー払い出し後に追加）

Teams の文字起こしを Microsoft Graph から取り出すキーを、小山が窓口に申請する（依頼文は `workato/窓口依頼_文字起こしキー.md`）。払い出されたら次のレシピを追加し、00_受付 に置く手作業をなくす。既存の `REC_定例議事録作成` は変更しない。

| # | アクション | 設定・ポイント |
|---|---|---|
| T | トリガー：スケジュール | 定例の日の夕方（例：毎週金曜 17:00・18:00・19:00 の3回）。会議が延びても拾えるようにする |
| 1 | HTTP（Microsoft Graph、小山のアカウントの委任アクセス） `GET /me/onlineMeetings/{会議ID}/transcripts` | `{会議ID}` は工事設定に持つ。定例は毎回同じ Teams 会議（定期的な予定）なので、最初に一度 `GET /me/onlineMeetings?$filter=JoinWebUrl eq '{定例の参加URL}'` で調べて登録する |
| 2 | データテーブル「取得済み文字起こし」と照合 | まだ取得していない文字起こし ID だけを残す（二重に格納しないため） |
| 3 | 繰り返し：`GET /me/onlineMeetings/{会議ID}/transcripts/{ID}/content?$format=text/vtt` | |
| 4 | Box：アップロード | 00_受付 に `{createdDateTime を日本時間にした YYMMDD}_定例_文字起こし_{文字起こしIDの末尾6文字}.vtt`（先頭の日付で p1a が開催日を決める。分かれた文字起こしは REC_定例議事録作成 がつなげる） |
| 5 | データテーブルに文字起こし ID を記録 | |
| E | エラー時 | 共通レシピ：エラー通知。取得できなかったときは、従来どおり小山が手で 00_受付 に置けばよい |

工事設定に「会議ID」「定例の参加URL」の2項目を追加する。

## 動作確認
- `workato/python/` の5本は、いただいた議事録フォーマット（修正版4）と課題リスト（125WEST）で動作を確認済み。`p5_build_writes` の書き込み先は、以前の Office Scripts 版と同じ。
- `samples/sample_ai_output.json` は LLM の回答例。手順12の確認に使う。
- 本番前に、テスト用の定例フォルダ（`{日付}_第99回_定例会議`）を 901 に作って議題と課題リストを置き、短い Teams 会議の文字起こしを 00_受付 に置いて、開発環境 → テスト環境で通しで確認し、窓口に本番デプロイを依頼する（運用編）。
